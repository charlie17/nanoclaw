# /security-audit

Worf's weekly trifecta enforcement, mount audit, secret scan, and drift check.

## Inputs

All inputs are pre-assembled by the host orchestrator and bind-mounted read-only at `/workspace/extra/worf-scope/`:

- `worf-scope/mount-allowlist.json` — policy (upper-bound allowlist for container mounts)
- `worf-scope/registered_groups.json` — live registered groups with container_config
- `worf-scope/scheduled-tasks.json` — live scheduled_tasks rows
- `worf-scope/iptables-docker-user.txt` — DOCKER-USER chain rules (ordered)
- `worf-scope/iptables-forward.txt` — FORWARD chain rules
- `worf-scope/docker-ps.jsonl` — running/stopped containers (one JSON object per line)
- `worf-scope/container-inspect.json` — inspect output for running nanoclaw-* containers
- `worf-scope/skills-inventory.json` — container skills list with mtimes
- `worf-scope/nanoclaw-git-head.txt` — NanoClaw HEAD SHA
- `worf-scope/nanoclaw-git-status.txt` — `git status --porcelain` output
- `worf-scope/secret-scan.json` — host-side scan results: `[{path, pattern_name, matched_line_count}]` — no raw secret values
- `worf-scope/laforge-status.json` — LaForge health snapshot

Vault (read-write, scoped to `general/` per mount-allowlist.json) is at `/workspace/extra/vault/`.

## Output

Write `/workspace/extra/vault/logs/worf-audit.md`. Create the directory first with `mkdir -p /workspace/extra/vault/logs/`.

**Format:**

```
# Worf Security Audit — YYYY-MM-DD

## Summary
<N> PASS · <N> WARN · <N> FAIL. Generated by /security-audit at <ISO timestamp>.

## 1. Trifecta (network isolation)
PASS: <finding>
DETAIL: <specifics>

## 2. Mount Table Conformance
...

## 3. Secret Scan
...

## 4. Scheduled Tasks
...

## 5. Fork-Delta Drift
...

## 6. Skills Inventory
...

## 7. LaForge Health
...
```

**Line-start discipline (CRITICAL — orchestrator greps these):**
Every finding line MUST begin with exactly one of:
- `PASS: ` — check passed
- `WARN: ` — anomaly, not an invariant violation
- `FAIL: ` — invariant violation; triggers CRITICAL Telegram alert

No other prefixes. No leading spaces. Exactly as shown.

## Checklist

Execute these checks in order using **python3 stdlib only** for all JSON/file reads. No `sqlite3` CLI, no `jq` — neither is available in this container image.

### 1. Trifecta — network isolation

Read `/workspace/extra/worf-scope/iptables-docker-user.txt`. Parse the numbered rule lines.

Assert the following invariant (exact order required):
- Rule 1: ACCEPT for src 172.29.0.0/24 to dst 172.29.0.1, dpt 8181
- Rule 2: ACCEPT for src 172.29.0.0/24 to dst 172.29.0.1, dpt 3001
- Rule 3: ACCEPT for src 172.29.0.0/24 to dst 172.29.0.1, dpt 3128
- Rule 4: DROP for src 172.29.0.0/24 to any dst

Any deviation from this order or any unexpected rule inserted before rule 4 = `FAIL:`.
Port set {8181, 3001, 3128} present in first 3 rules but wrong order = `FAIL:`.
Extra ACCEPT rules after rule 3 but before the DROP = `FAIL:`.

Then read `iptables-forward.txt`. Verify DOCKER-USER chain is present. If absent = `WARN:`.

### 2. Mount table conformance

Read `mount-allowlist.json`. Extract `allowedRoots` array (each has `path`, `allowReadWrite`) and `blockedPatterns` array.

Read `registered_groups.json`. For each group that has a non-null `container_config`:
1. Parse `container_config` as JSON.
2. For each entry in `additionalMounts`:
   - Assert `hostPath` is a sub-path of one of the `allowedRoots` paths (expand `~` to `/home/ubuntu`). No match = `FAIL:`.
   - Assert no `hostPath` contains any `blockedPatterns` token (case-insensitive). Match = `FAIL:`.
   - Assert the `vault/private` path is never mounted by any group. Match = `FAIL:`.
   - If `allowReadWrite` is false for the matching root, assert `readonly: true` on the mount. Mismatch = `FAIL:`.

Read `container-inspect.json`. For each running nanoclaw-* container, compare live mounts (`.HostConfig.Binds` or `.Mounts`) against the `registered_groups` declared config for that group. Any live mount not declared in the group config = `WARN:` (orchestrator may have mounted a tmp prefetch dir — expected for worf; unexpected for others).

### 3. Secret scan

Read `secret-scan.json`. Parse as JSON array of `{path, pattern_name, matched_line_count}`.

For each entry where `matched_line_count > 0`:
- If `path` ends with `.env` (the `.env` credential file): `PASS:` — expected location for credentials; `.env` is not bind-mounted into any container.
- Otherwise: `FAIL:` — secret pattern found outside expected credential file. Include path and pattern_name in the FAIL line.

Cross-check `container-inspect.json`: for each running container, check `.Config.Env` list. Assert no entry's key (the part before `=`) matches `*_TOKEN` or `*_KEY` (case-insensitive). Any match = `FAIL:` — credential leaked into container env.

If `secret-scan.json` is empty or all entries are `.env`-only: `PASS:` for the secret scan section.

### 4. Scheduled tasks

Read `scheduled-tasks.json`. Parse as JSON array.

Expected active cron rows (these are the only system rows that should exist):
- id=`daystrom-midnight-reset-v1`, group_folder=`daystrom`, schedule_type=`cron`
- id=`daystrom-nightly-report-v1`, group_folder=`daystrom`, schedule_type=`cron`
- id=`daystrom-weekly-review-v1`, group_folder=`daystrom`, schedule_type=`cron`

For each active row:
- If id matches the above list: `PASS:`.
- If id starts with `task-worf-audit-` and status is `active` or `completed`: `PASS:` — one-shot orchestrator task row, expected.
- If id contains known user-created reminder patterns (id does NOT start with `daystrom-` and is not a worf audit row): `WARN:` — possible user reminder task; flag id for review.
- Any row with `prompt` containing shell commands, URLs, or exfil patterns (e.g. `curl`, `wget`, `http`, `rm -rf`): `FAIL:`.

### 5. Fork-delta drift

Read `nanoclaw-git-head.txt`. Extract the SHA. This check is `WARN:`-always in v1 (no stored baseline to compare against). Emit the current HEAD SHA for reference.

Read `nanoclaw-git-status.txt`. If the file is empty (clean working tree): `PASS:`. If non-empty: `WARN:` — uncommitted changes present. List the first 5 changed files.

### 6. Skills inventory

Read `skills-inventory.json`. Parse as JSON array of `{name, has_skill_md, skill_md_mtime}`.

For each skill entry:
- If `has_skill_md` is false: `WARN:` — skill directory exists without SKILL.md.
- If `has_skill_md` is true: `PASS:`.

Report total skills count.

### 7. LaForge health

Read `laforge-status.json`.

If `missing` key is true: `WARN:` — LaForge not producing health status snapshot.

Otherwise, check common health fields:
- If any field indicates a service failure, stale container, or disk above threshold: `WARN:`.
- If all fields look healthy: `PASS:`.

Report the LaForge snapshot timestamp if available.

### 8. Write output

After completing all checks above, write `/workspace/extra/vault/logs/worf-audit.md`.

Structure:
1. H1: `# Worf Security Audit — YYYY-MM-DD` (today's date)
2. `## Summary` with total PASS/WARN/FAIL counts and generation timestamp
3. One H2 per checklist section (§1–§7), each containing all finding lines for that section
4. Every finding line starts with exactly `PASS: ` / `WARN: ` / `FAIL: `

After writing, emit a brief stdout confirmation: `synthesis complete — worf-audit.md written`.
